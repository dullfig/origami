# Origami Re-brain: Function-Hooks Context Folding

**Date:** 2026-09-19
**Status:** Approved design, pre-implementation
**Supersedes:** the current PreCompact/SessionStart + MCP-server architecture (entire existing codebase is retired)

## Motivation

Origami v0 worked *around* Claude Code's compaction: a read-only PreCompact hook saved folds to disk, a SessionStart hook re-injected an index, and a separate Node MCP server exposed unfold tools. It could not control what compaction produced, required Python + Node + an `ANTHROPIC_API_KEY`, and — decisively — it only ever acted when compaction fired. With 1M-token context windows, compaction fires roughly weekly, so the plugin did nothing while sessions degraded anyway.

Two developments change the picture:

1. **Claude Code function hooks ("Claude Mods")** — early access in Claude Code >= 2.1.259 behind `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` (anthropics/claude-code#91870). A TypeScript hook module can programmatically trigger compaction (`$.session.compact()`), replace the compacted message list (`session.compact` event returning `{messages}`), call Haiku on the host credential (`$.model.complete`, `$.model.classify`), persist state (`$.fs`, `$.store`), and register tools (`$.tool.register`). Proven in production by `tamaratran/fast-jev-compaction`.
2. **The problem is context quality and cost, not context exhaustion.** Model performance degrades well before large windows fill (Lost in the Middle, arXiv:2307.03172; arXiv:2510.05381), and every turn re-reads the full prefix at real cost and latency. The system must keep the live working set lean *continuously*, independent of window size.

## Goals

- Keep the live context lean at all times: verbatim conversation text plus short fold stubs, with bulky stale tool output folded to disk.
- Every fold leaves an always-visible stub written by a model that saw the full content (no judging content sight-unseen — the structural flaw of Jev-style scoring).
- On-demand recovery: a `hydrate(fold_id)` tool returns full content at the tail (prompt-cache-friendly), with hysteresis so thrashing content gets pinned.
- Zero external dependencies: no separate API key, no third-party services, no Python, no separate MCP server process.
- Never worse than stock: any internal failure falls back to Claude Code's built-in compaction.
- Log every hydrate call as the future training set for anticipatory prefetch.

## Non-goals (v1)

- Anticipatory pre-hydration (v2+, driven by the hydrate log).
- Range hydration (`hydrate(id, lines)`): whole-fold only until the log shows it matters.
- Fallback tiers for sessions without the function-hooks flag (classic-hooks `updatedToolOutput` mode and transcript-synthesis mode are documented options for a future public release, not built now).
- Migration of v0 fold state (`.claude/context-folding/`): fresh start.
- A `list_folds` tool or `/fold-status` command: the stubs in context *are* the index.
- Handling `session.compact` events with `trigger: "precompute"`: skipped in v1.

## Architecture

One TypeScript function-hooks module; no other runtime components.

```
origami/
├── .claude-plugin/plugin.json      # userConfig (thresholds, budgets)
├── hooks/
│   ├── hooks.json                  # { "modules": ["./origami.ts"] }
│   ├── origami.ts                  # hook registrations and wiring only
│   ├── rebuild.ts                  # pure: (messages, decisions) → messages
│   ├── librarian.ts                # Haiku scoring + stub writing
│   └── store.ts                    # fold persistence over $.fs / $.store
├── skills/context-folding/SKILL.md # teaches the model to live with stubs and hydrate
├── types/claude-code.d.ts          # generated by /plugin-types; pinned per CC version
└── tests/                          # rebuild unit tests + 'claude-code/testing' hook tests
```

Deleted: `core/*.py`, `server/index.js`, `hooks/precompact.py`, `hooks/sessionstart.py`, `commands/*`, `requirements.txt`, `package-lock.json` (v0), the README's v0 install prerequisites.

Prerequisites after re-brain: Claude Code >= 2.1.259 with `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`. Nothing else.

### Component: Fold Store (`store.ts`)

- Fold bodies: markdown files at `.claude/origami/folds/fold-NNN.md` via `$.fs.write` / `$.fs.read`. Body = the exact folded content plus a small header (tool, input, turn of origin).
- Fold index: `$.store` keys — per fold: id, stub text, state (`folded` | `pinned`), origin turn, size estimate, hydration count.
- Hydrate log: append-only `.claude/origami/hydrate.log` (JSONL: fold id, turns-since-fold, session id, timestamp). Written on every hydrate; never read by v1 logic.
- Both `$.fs` and `$.store` persist across `--resume` and restarts.

### Component: Librarian (`librarian.ts`)

Haiku via the host credential; batched into as few calls as possible per sweep.

- **Score:** given the sweep's candidates *with full content visible*, returns keep / fold per candidate. Implemented as one structured `$.model.complete({model: "haiku"})` call per sweep (chunked only if the candidate batch itself is huge); `$.model.classify` is the fallback shape if structured output proves unreliable.
- **Stub:** for each fold decision, writes a 1–3 line stub while the content is in view: what it is, what it contains, what one would ask for. Example: `fold-012: Read src/auth.ts (480 lines) — JWT validation, refresh flow, SECRET_ROTATION constant.`

Invariant: the librarian always sees the content it judges. No optimization may replace candidate content with omission notes in the librarian's input.

### Component: Rebuilder (`rebuild.ts`)

Pure function `(messages, decisions, foldIndex) → { messages, tokensBefore, tokensAfter }`. Invariants (all unit-tested without the harness):

1. User and assistant text preserved verbatim and in order.
2. A `tool_result` is never orphaned from its `tool_use`; parallel tool-call siblings stay intact.
3. A folded result is replaced by its stub plus fold id in the result slot.
4. The first message and the newest `preserveRecentTurns` turns are never touched.
5. Pinned folds are restored inline (full content) and marked ineligible.
6. If estimated reduction < `minReductionRatio`, returns a "not worth it" signal instead of messages.

### Component: Hook wiring (`origami.ts`)

Three registrations:

1. **`turn.complete` — trigger policy.** Estimate the mass of fold candidates: unpinned tool results older than `foldAgeTurns` turns. If candidate mass >= `minFoldMass` tokens, `await $.session.compact()` (in-flight guard, fast-jev pattern). Additionally, if live context exceeds `workingSetBudget` absolute tokens, the next sweep runs aggressive: `foldAgeTurns` is treated as 1 and the librarian prompt states that the working set is over budget and to fold everything not clearly needed. Context-window percentage is never consulted; behavior is identical at 200k and 1M windows.
2. **`session.compact` — the interceptor.** Fires for plugin-triggered sweeps, manual `/compact`, and the (rare) auto-threshold — one path. Assemble candidates → librarian scores and writes stubs → store persists bodies and index → rebuilder produces messages → return `{messages, tokensBefore, tokensAfter}`. On *any* failure (model error, fs/store error, unparseable librarian output, insufficient reduction on a real compaction) → `next(event)`: built-in compaction runs; on insufficient reduction for a plugin-triggered sweep → `{skip}` (nothing needed doing).
3. **`hydrate(fold_id)` — registered tool.** Reads the fold body, returns it as the tool result (lands at the tail; prefix cache untouched). Increments hydration count; at 2, the fold is pinned: next sweep restores it inline permanently. Every call appended to the hydrate log. Unknown fold id → error result naming the valid id format, never a throw.

### Skill (`skills/context-folding/SKILL.md`)

Rewritten to teach the main model: stubs mean "you once knew this in full"; call `hydrate` before re-running a tool to recover known content (a re-read may not be idempotent — files change, tests flake); hydrated content may fold again after use; repeated need pins automatically.

## Flow

```
turn ends ──► turn.complete: stale unpinned tool-result mass ≥ minFoldMass?
                        │ no → nothing (window fill is irrelevant)
                        │ yes
                        ▼
              $.session.compact()      (manual /compact and auto-compact
                        │               arrive at the same interceptor)
                        ▼
              session.compact hook
                        │  candidates = unpinned results older than foldAgeTurns
                        ▼
              Librarian (Haiku, full content visible)
                        │  keep / fold + stub per candidate
                        ▼
              Store: bodies → $.fs, index → $.store
                        ▼
              Rebuilder → { messages }   (verbatim text + stubs, pairs intact)
                        │  any failure anywhere → next(event) or {skip}
                        ▼
              conversation continues ──► model calls hydrate(fold-012)
                                              │  full content at tail; count++;
                                              ▼  logged; 2nd hydrate → pinned
                                        eligible to refold on a later sweep
```

Because candidates age in at `foldAgeTurns`, accumulating mass sits near the tail; each sweep's cache invalidation extends only from the oldest new fold forward. Fold-young behavior emerges from the mass trigger — there is no second cadence.

## Configuration (`plugin.json` userConfig)

| Option | Default | Meaning |
| --- | ---: | --- |
| `foldAgeTurns` | 3 | Results younger than this are never candidates |
| `minFoldMass` | 20000 | Candidate token mass that triggers a sweep |
| `workingSetBudget` | 100000 | Absolute live-context tokens; above it, sweeps turn aggressive |
| `preserveRecentTurns` | 3 | Turns the rebuilder never touches |
| `minReductionRatio` | 0.15 | Below this, a sweep is skipped |
| `pinAfterHydrations` | 2 | Hysteresis threshold |
| `librarianModel` | `haiku` | Passed to `$.model.complete` |

Token counts estimated without a tokenizer (chars/4 heuristic, calibrated against `$.session.usage()` breakdown when available).

## Error handling

- Librarian failure, malformed output, store I/O failure: log via `$.ui.log`, then `next(event)` (real compaction) or `{skip}` (plugin sweep). The session must never be degraded below stock behavior.
- `hydrate` failures return error text as the tool result; they never throw out of the hook.
- In-flight guard prevents re-entrant sweeps; `$.session.compact()` rejects while a turn runs — caught and retried at the next `turn.complete`.

## Testing

- `rebuild.ts` invariants: pure unit tests, including orphaned-pair, parallel-sibling, pinned-restore, and below-ratio cases.
- Hook behavior: `claude plugin test` with the `'claude-code/testing'` kit (mock store, clock, env): trigger fires at mass threshold and not below; failure paths fall through to `next`; hydrate round-trip and pin-at-2.
- Manual smoke: a session filled with bulky reads; verify stubs appear, `hydrate` recovers content verbatim, second hydrate pins.

## Risks

- **Early-access surface.** The `$` API may change between Claude Code releases. Mitigation: pin `types/claude-code.d.ts` (regenerate with `/plugin-types` after upgrades), state the supported version in README — same discipline as fast-jev-compaction.
- **Cache cost.** Every sweep is a paid cache bust from the edit point. Mitigation: mass trigger keeps edits near the tail; `minReductionRatio` gate; measure with `tokensBefore/After`.
- **Librarian judgment.** A bad fold hides content behind a stub — recoverable via hydrate (the design premise: wrong guesses are page faults, not data loss), but chronic bad stubs erode trust. Mitigation: stub-quality eyeballing in smoke tests; hydrate log reveals systematically re-fetched folds.
- **Feature-flag dependency.** If Mods ships in changed form, the wiring layer (`origami.ts`) absorbs the change; rebuilder/librarian/store are surface-independent.

## Future (recorded, not built)

- Anticipatory prefetch trained on the hydrate log; deterministic triggers first (about to edit a file → pre-hydrate its last read).
- Range hydration if the log shows large folds hydrated for small slices.
- Classic-hooks (`updatedToolOutput`) degraded tier and transcript-synthesis floor for a public release.
- Fold summaries of *conversation sections* (v0's original granularity) on top of v1's tool-result granularity.
